/review

Revisa código PO-UI Angular contra regras de boas práticas, performance, acessibilidade, segurança, quirks PO-UI e cobertura de testes

/poui-specialist:review

Revisa componentes e serviços Angular / PO-UI contra um conjunto de regras categorizadas, gerando um relatório com severidade, código atual e sugestão de correção para cada achado.

Sintaxe

Categorias de foco

FlagRegras aplicadas
boas-praticasOnPush, tipagem, signals, unsubscribe, inject(), computed()
performancetrack/trackBy, lazy loading, computed() vs método, mutação de array
acessibilidadep-label, aria-label, p-help em campos com restrições
segurancabypassSecurityTrust*, URLs hardcoded, concatenação em parâmetros HTTP
pouipo-table selection, loading state, tipos de coluna inválidos, po-modal sem dismiss
qualidadeComponentes e serviços sem *.spec.ts correspondente
allTodas as categorias (padrão quando --focus não é informado)

Regras por categoria

Boas Práticas (BP)

IDSeveridadeRegra
BP-001CRITICALChangeDetectionStrategy.OnPush ausente
BP-002WARNINGUso de any em anotações de tipo
BP-003WARNINGObservable sem cleanup (takeUntilDestroyed, takeUntil, unsubscribe)
BP-004INFO@Input() legado em vez de input<T>() (Angular 17+)
BP-005INFO@Output()/EventEmitter legado em vez de output<T>()
BP-006WARNINGManipulação direta do DOM (document.querySelector, nativeElement.style)
BP-007WARNINGErro exibido via console.error ou alert em vez de PoNotificationService
BP-008INFOInjeção via construtor em vez de inject() em componente standalone
BP-009WARNINGNon-null assertion (!) em dados vindos de API HTTP
BP-010INFOEstado derivado como método puro quando deveria ser computed()

Performance (PERF)

IDSeveridadeRegra

PERF-002WARNINGChamada de método no template sem cache (signal ou computed)
PERF-003WARNINGRota com component: direto em vez de loadComponent (eager loading)
PERF-004INFOChamada HTTP no constructor() em vez de ngOnInit()
PERF-005WARNINGArray passado ao po-table mutado in-place (.push, .splice, .sort) — OnPush não detecta

Acessibilidade (A11Y)

IDSeveridadeRegra

A11Y-004INFOCampo com restrições de negócio (máscara, formato, faixa numérica) sem p-help

IDSeveridadeRegra

Formato do relatório

O relatório é gerado por arquivo, com severidades separadas e snippet do código atual + sugestão corrigida:

Em revisões com múltiplos arquivos, é exibida uma tabela resumo ao final com o total de achados por arquivo e por severidade.

/lint

Analisa componentes PO-UI Angular para os 18 quirks e anti-padrões conhecidos — reporta por severidade e corrige automaticamente os problemas com fix seguro

/test

Gera unit tests Karma + Jasmine para componentes e services PO-UI Angular
