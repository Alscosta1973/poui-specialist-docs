Como o Dark Mode funciona no PO-UI

PoThemeService.changeCurrentTheme(PoThemeTypeEnum.dark) aplica um atributo no elemento <body> que altera variáveis CSS customizadas (--color-*). Todos os componentes PO-UI usam essas variáveis internamente e adaptam automaticamente.

O que muda: apenas as variáveis CSS — nenhum arquivo adicional de CSS precisa ser carregado.

Pré-requisito: os arquivos CSS do tema PO-UI já devem estar configurados em angular.json (mesmo setup do tema claro — não é necessário arquivo extra para dark mode):

7. Armadilhas comuns

❌ background-color hardcoded em componente custom

Componentes PO-UI adaptam automaticamente, mas seus próprios componentes não. Qualquer #hex ou rgb() hardcoded em .component.scss vai parecer errado no dark mode. Fix: substituir por var(--color-*).

❌ Imagens e SVGs sem variante dark

Logotipos brancos somem no dark mode (fundo claro → fundo escuro inverte o contexto). Fix: usar filter: invert(1) condicionalmente ou fornecer variante da imagem:

❌ localStorage não disponível em SSR

Se o projeto usar Angular Universal / SSR, window.matchMedia e localStorage quebram no servidor. Envolva com verificação:

❌ PoThemeTypeEnum não importado corretamente

❌ Toggle sem persistência

Ao navegar entre rotas, PoThemeService mantém o tema na memória — mas ao recarregar a página, volta ao padrão. Sempre usar localStorage para persistir a preferência (como mostrado no ThemeService da Seção 1).

8. Integração com Protheus (contexto embarcado)

Quando o app roda dentro do Protheus (iframe), o usuário não tem acesso às configurações do SO. O comportamento recomendado:

  • Se o Protheus tiver API de preferência de tema → usar
  • Caso contrário → iniciar sempre em modo claro (default Protheus)
  • Expor o toggle apenas quando !proAppConfigService.insideProtheus()
