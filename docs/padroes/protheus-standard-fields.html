Referência estática — Campos padrão Protheus (SX3)

Referência embutida e autocontida (não depende de nenhum outro plugin instalado) para validar, no /poui-specialist:discover, o tamanho/tipo/obrigatoriedade dos campos padrão das tabelas Protheus mais comuns em integrações REST.

Atribuição: a estrutura de colunas do SX3 abaixo foi conferida contra a documentação do pacote advpl-specialist (MIT License, © Thalys Augusto) e a TDN pública da TOTVS. Os nomes/tamanhos de campo listados são schema público e estável do Protheus (não são segredo comercial de nenhum autor).

Limite desta referência

Cobre só campos padrão — os que vêm de fábrica em qualquer instalação Protheus. Não cobre campos customizados (prefixo X_*, ex: A1_XCODAGE), que variam por cliente e só podem ser confirmados consultando o dicionário de dados real (SX3) daquela instalação específica — algo que nenhum plugin Claude Code consegue fazer sem acesso direto ao banco/AppServer do cliente. Se o campo do endpoint não aparecer aqui, é provavelmente customizado: sinalize e não adivinhe o tamanho.

O que cada coluna SX3 significa (para interpretar o resultado)

Coluna SX3Significado
X3_CAMPONome do campo (ex: A1_COD)
X3_TIPOTipo: C Character, N Numeric, D Date, L Logical, M Memo
X3_TAMANHOTamanho do campo
X3_DECIMALCasas decimais (campos numéricos)
X3_OBRIGATObrigatório: S/N

Como casar o campo JSON com o campo SX3

O JSON do REST costuma vir em camelCase sem o prefixo de tabela (ex: codigo, nome, vencimento). Para casar com a tabela acima:

  1. Remover o prefixo da tabela do nome SX3 (A1_COD → cod)
  2. Comparar case-insensitive e ignorando underscore (nome ~ NOME, dataVencto ~ VENCTO)
  3. Se não achar correspondência em nenhuma linha da tabela informada → tratar como campo customizado (ver "Limite desta referência" acima)
