# Deploy para Produção

Guia completo para levar um app Angular + PO-UI + Protheus para produção.

## Build

```powershell
ng build --configuration production
```

Saída em `dist/<project>/browser/` com JS/CSS minificados e hash nos nomes de arquivo.

```powershell
# Análise de bundle
ng build --configuration production --stats-json
npx webpack-bundle-analyzer dist/<project>/browser/stats.json
```

Apps PO-UI típicos ficam entre **600 KB – 1.2 MB** no bundle inicial (sem gzip).

## Hospedagem

### IIS — web.config para SPA routing

```xml
<configuration>
  <system.webServer>
    <rewrite>
      <rules>
        <rule name="Angular SPA" stopProcessing="true">
          <match url=".*" />
          <conditions logicalGrouping="MatchAll">
            <add input="{REQUEST_FILENAME}" matchType="IsFile"      negate="true" />
            <add input="{REQUEST_FILENAME}" matchType="IsDirectory" negate="true" />
          </conditions>
          <action type="Rewrite" url="/index.html" />
        </rule>
      </rules>
    </rewrite>
  </system.webServer>
</configuration>
```

Salvar em `src/web.config` e declarar em `angular.json` → `assets`.

### nginx

```nginx
location / { try_files $uri $uri/ /index.html; }
location ~* \.(js|css|png|woff2)$ { expires 1y; add_header Cache-Control "public, immutable"; }
location = /index.html { add_header Cache-Control "no-cache"; }
```

### Protheus AppServer

Copiar `dist/<project>/browser/` para a pasta `web/` do AppServer e configurar `appserver.ini`.
Use `--base-href /meu-app/` no build se o app ficar em subdiretório.

## CORS

| Estratégia | Quando usar |
|-----------|------------|
| **Mesma origem via nginx proxy reverso** | Recomendado — zero CORS |
| **Headers CORS no ADVPL** | Origens diferentes; validar `Origin` — nunca usar `*` com credentials |
| **`MV_CORSORI`** | Quando suportado pela versão do Protheus |

## Autenticação em produção

`proxy.conf.json` só funciona em desenvolvimento. Em produção, o interceptor injeta o token:

```typescript
export const authInterceptor: HttpInterceptorFn = (req, next) => {
  const token = inject(ProAppConfigService).getTokenProtheus?.() ?? '';
  if (!token) return next(req);
  return next(req.clone({ setHeaders: { Authorization: `Bearer ${token}` } }));
};
```

**`po-upload` usa XHR** — o interceptor não intercepta. Use `[p-headers]` explicitamente:

```html
<po-upload [p-url]="uploadUrl" [p-headers]="{ Authorization: 'Bearer ' + token }">
</po-upload>
```

## Checklist pré-deploy

```
□ ng build --configuration production sem erros
□ Sem credenciais em arquivos versionados
□ proxy.conf.json no .gitignore
□ web.config (IIS) ou try_files nginx configurado
□ CORS testado com origem exata de produção
□ po-upload com [p-headers] configurado
□ Bundle inicial < 1 MB
□ Lazy chunks existem para cada módulo feature
□ ng test --watch=false passa 100%
```

## CI/CD (GitHub Actions)

```yaml
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: '20', cache: 'npm' }
      - run: npm ci
      - run: npm test -- --watch=false --browsers=ChromeHeadless
      - run: npm run build -- --configuration production
```

<Callout type="warning">
  `proxy.conf.json` contém endereços internos do AppServer — **nunca commitar**.
  O `/scaffold` já o adiciona ao `.gitignore` automaticamente.
</Callout>
