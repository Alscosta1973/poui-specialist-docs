# Changelog

## [1.10.0] — 2026-07-01

### Adicionado

**2 novos comandos**

- **`/migrate`** — converte componentes Angular legados (NgModule-based) para standalone + `OnPush` + signals. Analisa o componente, mapeia todas as mudanças necessárias (`@Input()` → `input()`, `@Output()` → `output()`, `*ngIf` → `@if`, atribuições → `.set()`), apresenta o plano antes de escrever e remove o componente do NgModule automaticamente.

- **`/lint`** — analisa componentes PO-UI para os 18 quirks e anti-padrões conhecidos e corrige automaticamente os que têm fix seguro: `OnPush` ausente, `ngAfterViewInit` faltando (Quirk #1), `*ngIf`/`*ngFor` legados, `p-selected-rows` inexistente (Quirk #6), `p-max-length` vs `p-maxlength` (Quirk #4), `subscribe()` sem `error:` callback.

**1 novo template**

- **`auth-login`** — tela de autenticação completa: `po-page-login` + `AuthService` com `localStorage` + `authGuard` funcional + `tokenInterceptor` (Bearer token) + endpoint TLPP de login com validação de usuário Protheus.

**Novos padrões e documentação**

- **Quick Start** (`docs/quickstart.md`) — guia "primeiro componente em 5 minutos": scaffold → generate → conectar ao Protheus → review → gerar tela de edição.
- **Troubleshooting** (`skills/poui-patterns/troubleshooting.md`) — 10 erros comuns com causa raiz e fix: `TypeScript >=5.9.0`, budget exceeded, `NG8002`, `TS2353`, tela em branco (Quirk #1), `po-table` invisível (Quirk #12), `po-dynamic-form` sem valores (Quirk #13), CORS, Latin-1, paginação duplicada.
- **Error Handling Protheus** (`skills/poui-patterns/protheus-error-handling.md`) — padrão único para tratamento de erros 400/500: função `parseProtheusError()` com decode Latin-1, tabela de status HTTP Protheus, regras obrigatórias para todo componente.

**Flags no `/scaffold`**

- `--with-dark-mode` — gera `ThemeService` singleton com toggle persistente em `localStorage`, detecção de `prefers-color-scheme` do sistema e SCSS dark-safe.
- `--with-i18n` — gera estrutura `src/i18n/` com dicionários PT-BR/EN e `providePoI18n()` configurado em `app.config.ts`.

**Suite de testes do plugin**

- `scripts/test-plugin.js` — 61 verificações automáticas: arquivos obrigatórios, versões sincronizadas, contagem de templates, ausência de `*ngIf/*ngFor` nos templates gerados, frontmatter nos comandos, quirks numerados sequencialmente, `@generated` headers atualizados. Rodar com `npm test`.

### Corrigido

- Quirk #21 renumerado para **#18** — numeração agora é sequencial de #1 a #18.
- `marketplace.json` — versão, contagens e lista de comandos sincronizados automaticamente a cada release.

## [1.8.0] — 2026-07-01

### Adicionado

**2 novos comandos**

- **`/discover`** — auto-descobre o contrato de um endpoint REST Protheus ou arquivo `.prw`/`.tlpp`.
  Detecta campos, tipos e ações; produz um manifesto de descoberta + comando `/generate` pronto para uso.
  Flag `--suggest-batch` gera o manifesto completo (list + edit + service + models).
  Se o endpoint estiver fora do ar, aceita JSON colado manualmente.

- **`/scaffold`** — cria um projeto Angular 17+ completo com PO-UI do zero.
  Configura automaticamente: `angular.json` (styles PO-UI), `tsconfig.json` (`strict: false`),
  `app.config.ts`, `app.routes.ts`, shell com `po-menu + po-toolbar`, environments,
  `proxy.conf.json` (adicionado ao `.gitignore`) e instalação de todos os pacotes TOTVS.
  Flag `--demo` cria uma `HomeComponent` com 3 `po-widget` de boas-vindas.

**3 novos tipos de geração**

- **`upload`** — 3 variações prontas para uso com Protheus:
  - **Template A** — single auto-upload (PDF/imagem) com `po-upload` + signal `uploadDone`
  - **Template B** — múltiplos arquivos com tabela de resultados e contador de pendentes
  - **Template C** — upload embutido em formulário (envio manual via `FormData`)
  - Quirk documentado: `po-upload` usa XHR internamente — interceptors Angular não interceptam;
    token deve ser fornecido via `[p-headers]`

- **`infinite-scroll`** — lista com carregamento incremental via `IntersectionObserver`:
  - `rootMargin: '150px'` para pré-carregar antes do sentinel chegar ao viewport
  - Duplo guard: `if (loadingMore() || !hasNext()) return` evita chamadas duplicadas
  - `ngOnDestroy()` desconecta o observer — sem memory leak
  - Variante com cursor/keyset pagination
  - Nota: `IntersectionObserver` roda fora da Zone.js — signals funcionam; `EventEmitter` precisa de `NgZone.run()`

- **`po-tree`** — árvore hierárquica com dois templates:
  - **Template A** — flat-to-tree: converte lista plana em `PoTreeViewItem[]` com `buildTree()` recursivo
  - **Template B** — lazy loading: carrega filhos sob demanda via `(p-expanded)` + REST;
    usa `Set<string>` para cache e prevenção de chamadas duplicadas
  - Layout master-detail com painel de detalhes em 2 colunas
  - Quirk: `subItems: []` = tem filhos (mostra ícone expand); `subItems: undefined` = folha

**3 novos padrões**

- **Dark Mode** (`po-ui-patterns-dark-mode.md`) — `ThemeService` singleton com:
  - `signal<'light'|'dark'>` reativo para binding no template
  - Persistência em `localStorage` com prioridade sobre `prefers-color-scheme`
  - Detecção em tempo real de mudança de preferência do SO
  - Tabela de variáveis CSS `var(--color-*)` que adaptam automaticamente
  - Integração Protheus: sempre light dentro do iframe

- **Internacionalização** (`po-ui-patterns-i18n.md`) — guia completo com `PoI18nService`:
  - Setup `providePoI18n()` com lazy-load de dicionários JSON por contexto
  - Detecção automática do idioma Protheus (`POR`→`pt`, `ENG`→`en`, `SPA`→`es`)
  - Signal tipado `lit` para evitar typos em runtime
  - Solução para `po-table.label` vazio quando `getLiterals()` resolve após init
  - 3 regras de review: I18N-001, I18N-002, I18N-003

- **Deploy para Produção** (`po-ui-patterns-deployment.md`) — guia de deploy com:
  - `ng build --configuration production`, budgets e análise de bundle
  - IIS (`web.config` URL Rewrite), nginx (`try_files`) e Protheus AppServer
  - 3 estratégias CORS: mesma origem via proxy nginx, headers ADVPL, `MV_CORSORI`
  - `HttpInterceptorFn` com `getTokenProtheus()`; nota crítica sobre `po-upload` + XHR
  - `environment.ts` vs `environment.prod.ts` com `fileReplacements`
  - Checklist de 13 itens + GitHub Actions CI/CD completo

## [1.7.0] — 2026-07-01

### Adicionado

**3 novos tipos de geração (família Infraestrutura)**

- **`http-interceptor`** — interceptors funcionais Angular 17+ (`HttpInterceptorFn`). Três variantes prontas para uso no Protheus:
  - **Auth token**: injeta `Bearer` token do `ProAppConfigService` em toda requisição; sem-op quando fora do Protheus
  - **Error translation**: captura `HttpErrorResponse`, decodifica mensagens Latin-1 do Protheus via `TextDecoder('iso-8859-1')` e exibe via `PoNotificationService`
  - **Loading overlay**: exibe overlay global para toda requisição HTTP; suporta header `X-Skip-Loading` para suprimir por request; companion `LoadingService` com contador de requisições concorrentes
  - Registro em `app.config.ts` via `provideHttpClient(withInterceptors([...]))`

- **`route-guard`** — guards funcionais Angular 17+ (`CanActivateFn`, `CanDeactivateFn`). Três variantes:
  - **Auth Protheus**: verifica `proAppConfigService.insideProtheus()` antes de ativar rota
  - **Unsaved changes**: `CanDeactivateFn<HasUnsavedChanges>` com interface exportada que componentes de formulário implementam; confirma antes de navegar
  - **Permission guard**: lê `route.data['requiredPermission']` e valida perfil do usuário Protheus; suporte a perfil `ADMIN` como bypass

- **`standalone-migrate`** — guia de migração NgModule → Angular 17+ standalone. Inclui:
  - Checklist pré-migração (NgModule, imports de template, injeção, `@Input/@Output`, lifecycle, `ChangeDetectionStrategy`)
  - Transformation map completo: `@NgModule` → standalone, `CommonModule` → imports individuais, construtor → `inject()`, `@Input/@Output` → `input()/output()`, `takeUntil(destroy$)` → `takeUntilDestroyed()`
  - Before/after completo com código TypeScript real
  - Limpeza do NgModule: como remover ou adaptar o módulo original
  - Atualização de rota: `component:` direto → `loadComponent` lazy
  - Pitfalls comuns: tela em branco (falta `ngAfterViewInit`), `NG0304` (imports faltando), `input()` retorna `Signal<T>` no template

**code-reviewer expandido — de 3 para 6 categorias, de 11 para 21 regras**

## [1.5.1] — 2026-06-25

### Corrigido

- **Tela em branco ao navegar pelo menu (OnPush + po-page-\*)** — Todos os 12 templates de componente agora incluem `ngAfterViewInit() { setTimeout(() => this.cdr.detectChanges()); }`. Sem esse padrão, navegar pelo menu deixava a tela em branco até o usuário clicar. `markForCheck()` em `ngOnInit` era insuficiente pois não dispara um ciclo de CD automaticamente quando nenhum zone-event ocorre após o init. Afeta: `page-list`, `page-dynamic-search`, `page-edit`, `page-detail`, `modal-crud`, `master-detail`, `stacked-browse`, `two-panel-browse`, `stepper-form`, `dashboard`, `action-list`, `page-dynamic`.

- **`escape()`/`unescape()` deprecated em `parseProtheusError`** — Substituído por `TextDecoder('iso-8859-1')` em 8 templates para decodificação correta de strings Latin-1 do Protheus sem funções removidas do padrão ECMAScript. Afeta: `page-list`, `page-dynamic-search`, `page-edit`, `page-detail`, `modal-crud`, `master-detail`, `stepper-form`, `action-list`.

- **`po-ui-quirks.md` — Quirk #1 atualizado** — Corrigido `markForCheck()` → `detectChanges()` com root cause ampliado: não é só o `contentOpacity` do `PoPageContentComponent` — o problema é mais amplo e afeta todo `ng-content` projetado em `po-page-*` com OnPush.

### Adicionado

- **Quirk #14 — PO-UI `@Input()` não faz auto-unwrap de signals Angular** — Componentes PO-UI leem seus `@Input()` de forma imperativa nos lifecycle hooks, recebendo o objeto `Signal` em vez do valor quando `()` é omitido. Sempre usar `[p-breadcrumb]="breadcrumb()"` em vez de `[p-breadcrumb]="breadcrumb"`.
